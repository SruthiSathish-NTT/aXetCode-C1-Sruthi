existing commands (`summary`, `timeline`, `grep`).  Default terminal output is

## JSON schema / field documentation

### `logscope summary --format json`

```json
{
  "command": "summary",
  "file": "<path to log file>",
  "counts": {
    "INFO":  <int>,
    "WARN":  <int>,
    "ERROR": <int>
  },
  "top_errors": [
    { "message": "<string>", "count": <int> }
  ],
  "first_timestamp": "<YYYY-MM-DDTHH:MM:SS>" | null,
  "last_timestamp":  "<YYYY-MM-DDTHH:MM:SS>" | null,
  "malformed_lines": <int>
}
```

- `top_errors` is ordered descending by count; at most 5 entries.
- Timestamps use `datetime.isoformat()` (no timezone suffix for naive datetimes).
- Both timestamp fields are `null` when the file contains no valid lines.

### `logscope timeline --format json`

```json
{
  "command": "timeline",
  "file": "<path to log file>",
  "bucket": "<spec>",
  "timeline": [
    { "bucket_start": "<YYYY-MM-DDTHH:MM:SS>", "error_count": <int> }
  ],
  "malformed_lines": <int>
}
```

- `timeline` is sorted chronologically; only non-empty buckets appear.
- `bucket_start` uses `datetime.isoformat()`.

### `logscope grep --format json`

```json
{
  "command": "grep",
  "file": "<path to log file>",
  "level": "INFO" | "WARN" | "ERROR",
  "since": "<YYYY-MM-DDTHH:MM:SS>" | null,
  "match_count": <int>,
  "matches": ["<raw log line>", ...],
  "malformed_lines": <int>
}
```

- `since` is `null` when `--since` is not supplied; otherwise the value is
  re-formatted from `YYYY-MM-DD HH:MM` to ISO-8601 via `parse_since().isoformat()`.
- `matches` preserves original file order; trailing newlines are stripped.

## Markdown report filename strategy

Pattern: `logscope-<command>-<YYYYMMDD>-<HHMMSS>.md`

- Written to the **current working directory**.
- The timestamp comes from `datetime.now()` at the moment the function is
  called — deterministic to the second and collision-safe across separate runs.
- Examples:
  - `logscope-summary-20261001-090015.md`
  - `logscope-timeline-20261001-090015.md`
  - `logscope-grep-20261001-090015.md`
- The `now` parameter in each `write_*_md()` function can be overridden by
  callers (used in tests to inject a fixed timestamp).

## How input processing remains streaming

M5 adds no new I/O.  Every command still delegates to the same `iter_log()`
generator introduced in M1 via the unchanged `run()` functions in
`commands/summary.py`, `commands/timeline.py`, and `commands/grep.py`.  The
format flag is tested *after* `run()` returns — it only affects how the
already-computed result object is serialised, never how the log file is read.
Memory use and streaming guarantees are identical to M1–M4.

None.  `pip install -e .` from M1 is still sufficient.  No new runtime
