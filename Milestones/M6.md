## Generator script

### Location

`scripts/gen_log.py`

The spec asks for `scripts/gen_log` (no extension). On Windows, Python
scripts require the `.py` extension to be importable and executable via the
`python` interpreter. The file is therefore `scripts/gen_log.py`. The exact
invocation is:

```bash
python scripts/gen_log.py --size-mb 100 --output synthetic-100mb.log
```

### CLI interface

| Argument | Default | Description |
|----------|---------|-------------|
| `--size-mb` | `100.0` | Target file size in megabytes |
| `--output` | `synthetic.log` | Output file path |
| `--malformed-rate` | `0.02` | Fraction of lines that are malformed (0.0–<1.0) |
| `--seed` | none | Optional integer seed for reproducibility |

### How the generator avoids loading the output into memory

`generate()` opens the output file and writes **one line at a time** inside a
`while written_bytes < target_bytes` loop. No list of lines is accumulated.
The only state held in memory between iterations is:

- `current_ts` — a single `datetime` object
- `written_bytes`, `valid_count`, `malformed_count` — three integers
- the `random.Random` instance

This means memory use is O(1) regardless of target file size.

---

## How Logscope remains streaming during analysis

The analysis commands (`summary`, `timeline`, `grep`) call `iter_log(path)`,
which opens the file and yields one `LogEntry | MalformedLine` at a time via
`for line in fh`. No command reads the file into a list or buffer. The
generated 100 MB file is processed exactly the same way as a 1 MB file.

## Setup / run-instruction changes

- The generator requires no new dependencies — `random`, `datetime`, and
  `argparse` are all standard library.
- `pip install -e .` from M1 remains the only install step.
- `synthetic-100mb.log` is a generated test artifact and is **not** included
  in the handoff. Regenerate it with:
  ```bash
  python scripts/gen_log.py --size-mb 100 --output synthetic-100mb.log --seed 42
  ```
